# 文明记忆、记录与纠偏机制

文档编号：`FSP-CIV-ARCH-03`  
状态：`RESEARCH_NOTE / NON_NORMATIVE / IN_REVIEW`

## 1. 记忆不只是保存

**OBSERVED**：长期系统会通过事件记录、文本保存和制度记忆保留对过去的引用。

**INTERPRETATION**：记忆可以被分析为事件、来源、版本、缺口、竞争解释和后续纠正的组合。

**HYPOTHESIS**：可追溯记忆可能帮助系统在代际更替后维持责任和连续性。

长期系统如果每一代都重新初始化，就无法解释自己为何成为现在的样子。但保存也不自动产生可信记忆。记忆至少包含事件、记录者、来源、版本、缺口、竞争解释和后续纠正。

```text
Event -> Record -> Preservation -> Interpretation -> Correction -> Reuse
```

## 2. 日志与历史的差别

**OBSERVED**：系统日志通常记录预定义事件，历史记录则包含选择、叙事和权力关系。

**INTERPRETATION**：史官传统与现代 Observer 只能在“记录和回看”的功能问题上有限类比。

**LIMITATION**：本研究不把史官称为古代 Observer，也不把历史记录自动视为 Evidence Package。

系统日志通常记录预定义事件；历史记录包含选择、叙事和权力。把史官称为“古代 Observer”会隐藏两者的尺度与责任差异。可借鉴的是功能问题：谁记录、记录什么、能否篡改、后人如何找到原始材料、纠正是否覆盖历史。

## 3. Correction 而非覆盖

**PROPOSED**：治理系统可以把纠偏建模为原始证据加上可归因的追加修订，而不是静默覆盖。

**HYPOTHESIS**：保留原始判断和修订理由，可能提高未来主体重审证据边界的能力。

纠偏机制应保留原始记录，并追加可归因的修订：

```text
Original Evidence
  + Correction
  + reason
  + author and authority
  + timestamp and version
```

这能防止“最终结论”抹掉判断过程，也允许未来主体重审当时的证据边界。

## 4. 遗忘与废止

**INTERPRETATION**：长期记忆必须同时处理保存、限制访问、废止和合法删除之间的张力。

**LIMITATION**：本节不提出具体法律、隐私或数据保留政策。

长期系统并非保存越多越好。隐私、伤害、错误知识与无效规则可能需要限制访问、废止或合法删除。关键是区分内容不可继续使用与其曾经存在的治理事实是否仍需留痕。

## 5. 工程研究问题

以下是 `PROPOSED` 研究问题，不是现有版本的实现声明：

- Evidence 是否具有稳定身份与版本？
- Correction 是否追加而非静默覆盖？
- Replay 是否绑定当时的知识和 Engine 版本？
- 缺失记录是否显式成为 UNKNOWN？
- 谁能读取、纠正、废止或授权重放？

这些问题可供 Observer 与 Knowledge Governance 研究，但本文不声明现有版本已经全部实现。
