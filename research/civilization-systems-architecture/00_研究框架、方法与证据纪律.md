# 研究框架、方法与证据纪律

文档编号：`FSP-CIV-ARCH-00`  
状态：`RESEARCH_FRAMEWORK / NON_NORMATIVE / IN_REVIEW`

## 1. 研究问题

本系列不研究“哪个文明最好”，而研究长期运行系统的共同难题：系统在人员、制度、知识、技术和价值解释持续变化时，如何保留可追溯的连续性，同时允许必要的纠偏与重构？

这里的连续性不是静止：

```text
Continuity != unchanged components
Continuity = traceable identity + memory + migration + responsibility + correction
```

## 2. 分析维度

| 维度 | 问题 |
|---|---|
| 存续 | 系统如何避免整体崩溃？ |
| 自由 | 主体保留多少真实选择空间？ |
| 差异 | 不同传统如何共存、互操作或和平分离？ |
| 记忆 | 事件、来源和责任如何跨代保存？ |
| 迁移 | 旧语义如何进入新制度和新版本？ |
| 纠偏 | 错误如何被发现、记录、撤回和修复？ |
| 边界 | 哪些差异不能兼容，谁有权裁定？ |

## 3. 证据分层

`OBSERVED` 必须指向可检查来源；`INTERPRETATION` 可以存在竞争解释；`HYPOTHESIS` 必须容纳反例；`PROPOSED` 只是待验证的设计启示。任何历史材料都不能直接把某项能力升级为 `IMPLEMENTED` 或 `RUNTIME_VERIFIED`。

## 4. 禁止的一一对应

以下表达只可作为有限结构类比，不能作为事实等式：

```text
史官 != Observer
历史记录 != Evidence Package
天下 != Protocol Network
道 != Engine or algorithm
文明连续性 != production readiness
```

## 5. 研究方法

每个案例至少需要：来源说明、时间和地域边界、竞争解释、反例、受益者与受损者、连续与断裂的不同维度，以及对工程映射的限制。跨文明比较必须使用同一组问题，但不强迫不同文明共享同一答案。

## 6. 成功标准

成功不是证明 Full Spectrum 正确，而是提出可以被否证的假设，帮助工程团队设计更清楚的版本、身份、证据、迁移、UNKNOWN 和人工授权边界。
