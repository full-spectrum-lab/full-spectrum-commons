## 文档定位

本文不属于 Full Spectrum Protocol、Schema、代码、CI、测试、Evidence 或运行时权限来源。它提供多个并行的观察入口，解释为什么不同专业背景的人会看到 Full Spectrum 的不同切面。

“七条路径”不是认知等级、人员等级或必须依次完成的升级路线。读者可以从任何路径进入，也可以在路径之间往返。任何高层解释都必须回落到负责仓库的合同、代码、测试和 Evidence。

## 核心命题

跨层系统容易遭遇一种结构性误读：观察者使用自己熟悉的单一模型解释整个系统。例如，只把 Observer 看成监控工具，或只把 Protocol 看成权限管理。局部描述可能成立，但不能自动覆盖其他尺度。

Full Spectrum 同时涉及 AI 运行、组织责任、多主体协作、知识版本、长期演化和人机关系。因此，不同观察不是互相否定，而是同一候选治理结构在不同问题尺度下的投影。

## 路径一：AI 治理工具

**看到什么：**风险检测、告警、报告、约束和人工复核入口。

**适合谁：**普通用户、产品人员和第一次接触项目的人。

**容易误读：**把整个体系压缩成单一安全工具，忽略谁拥有治理权、知识依据和责任边界。

**当前可验证：**公开仓库包含本地运行、结构化结果、合成案例和范围化 Release Evidence。

**不得推断：**不能推断它是通用 AI 安全产品、生产控制器或自动裁决系统。

## 路径二：身份与权限结构

**看到什么：**主体、身份、角色、能力、授权和行动边界。

**适合谁：**工程师和系统架构师。

**容易误读：**把 Protocol 等同于 IAM 或 RBAC，忽略证据、知识版本、责任和事后复核。

**当前可验证：**Protocol 已公开相关草案、Schema、示例和一致性检查。

**不得推断：**不能推断已经形成通用身份网络、认证机构或跨组织生产授权系统。

## 路径三：审计与证据结构

**看到什么：**Observation、Evidence、Audit、Receipt、Snapshot 和 Replay。

**适合谁：**安全、质量、合规和复核人员。

**容易误读：**把 Observer 等同于通用日志、APM 或 Token 追踪平台。

**当前可验证：**Observer、Engine 和 Knowledge Governance 各自保存范围化证据、审计或回放材料。

**不得推断：**不能推断三仓所有路径已经形成生产级分布式事务或通用审计网络。

## 路径四：跨主体治理基础设施

**看到什么：**人、组织、模型、Agent、知识系统和外部环境之间的权责分离、冲突处理和责任保持。

**适合谁：**大型组织、协议设计者和治理研究者。

**容易误读：**把架构方向写成已经建成的公共治理网络。

**当前可验证：**各仓库的责任边界、合同方向和独立使用方式已经公开。

**不得推断：**不能推断真实跨组织网络已经运行，也不能推断 Full Spectrum 拥有参与方的治理权。

## 路径五：关系递归结构

**看到什么：**同一主体在不同关系中可能同时是行动者、治理参与者、受治理对象或证据提供者。

**适合谁：**复杂系统和组织研究者。

**容易误读：**把“递归”理解成无限嵌套、无限权限或同一套实现可以无条件扩展到所有尺度。

**当前可验证：**项目文档持续要求身份、关系、授权范围和 Evidence 分离。

**不得推断：**不能由递归概念推出普遍有效性、无限可扩展性或完成多尺度运行验证。

## 路径六：价值到工程的候选翻译

**看到什么：**责任、因果、边界和纠错等价值语言，可以尝试映射到工程对象。

| 价值语言 | 候选工程映射 |
|---|---|
| 责任 | Action Owner、责任引用和人工决定记录 |
| 因果 | Event Reference 和 Evidence Chain |
| 纠错 | Replay、恢复、撤销和追加式更正 |
| 边界 | Authorization、Capability 和 Scope |
| 减少伤害 | Safety Constraint、Fail-closed 和人工复核 |

**容易误读：**把候选映射写成语义等价。例如，`Action Owner` 不是责任的全部含义，Replay 也不等于完整纠错机制。

**当前可验证：**负责仓库已经实现或设计了部分对应对象和边界。

**不得推断：**不能声称传统思想已被完整形式化，或某个字段自动实现了相应价值。

## 路径七：悲悯协议作为稳定性约束假设

**看到什么：**在多主体、长期交互、影响传播、责任延迟和不确定性并存时，某些约束模式可能反复出现：权限不能无限扩大，代价不能无限外包，不确定性不能被隐藏，纠错和退出路径不能被取消。

**适合谁：**长期治理、伦理和文明系统研究者。

**容易误读：**把候选治理假设写成宇宙规律、宗教权威或已实现安全性质。

**当前可验证：**工程仓库中存在边界、`UNKNOWN`、Evidence、Replay 和失败关闭等有限机制。

**不得推断：**不能由这些机制证明“悲悯”已经被完整实现，也不能据此产生任何工程权限。

## 路径之间的关系

这些路径不是“第一条错误、第七条正确”。更准确的关系是：

```text
工具入口 ─┐
权限结构 ─┤
证据结构 ─┼→ 同一项目的不同观察镜头 → 回落到责任仓库和 Evidence
跨主体治理┤
关系递归 ─┤
价值翻译 ─┤
稳定性假设┘
```

## 公共理解原则

1. 不要求观察者一次理解全部结构。
2. 允许工程、治理和研究等不同入口并存。
3. 不以抽象程度判断读者高低。
4. 高层解释不能覆盖低层工程事实。
5. 任何能力主张必须按以下顺序回落：

```text
解释 → 候选原则 → Protocol / Schema → 代码与测试
     → 固定运行 → Evidence / Replay → 范围化结论
```
