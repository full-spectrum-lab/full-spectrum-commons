本清单用于检验一个没有项目背景的读者，能否仅依靠公开 GitHub 材料形成准确、不过度的理解。它不是能力测试，也不要求读者接受项目观点。

## 复核条件

- 不向复核者提供私下讲解；
- 从 [GitHub Organization 首页](https://github.com/full-spectrum-lab) 开始；
- 最多阅读 30 分钟；
- 只允许使用公开链接；
- 记录找不到、看不懂和无法确认的内容，不猜测。

## 十分钟基础问题

1. 请用两句话说明 Full Spectrum 解决什么问题。
2. 它是不是 AI 模型、Agent 编排器或生产控制器？
3. Protocol、Engine、Observer、Knowledge Governance 各自负责什么？
4. 哪个主体最终执行现实动作？
5. 当前是否已经生产就绪？
6. 在哪里查当前 Release、测试和 Evidence？

## 三十分钟边界问题

1. 固定场景验证是否等于一般兼容？
2. 架构图是否证明所有连接已经实现？
3. 研究文章能否覆盖代码、Schema 或 Release 事实？
4. 悲悯协议、全息递归等概念与工程实现是什么关系？
5. 如果证据不足，系统应如何表达？
6. 如何提交批评、反例或边界问题？

## 通过标准

复核者应能准确表达：

- 项目关注身份、授权、知识版本、确定性判断、Evidence、Replay 和责任；
- 四条工程轨道可以独立使用，组合需要明确合同；
- 最终现实动作属于获得授权的外部行动者或业务系统；
- 当前公开证据不支持生产级跨组织网络、一般兼容或自动现实行动；
- 研究概念是解释和假设，不是运行权限或实现证明。

任何关键问题回答错误，结论应为 `PUBLIC_UNDERSTANDING_GAP_FOUND`，并记录导致误读的页面和措辞。
