# GitHub Community Stage-1 Plan

This document describes the first public community stage for Full Spectrum on GitHub.

## Goal

Stage 1 is not about proving a complete protocol network.

Stage 1 is about proving three smaller things:

1. people can understand the repository structure;
2. people can run or inspect something real;
3. people are willing to react, question, reuse, or contribute.

## Success signals

We treat the following as the main Stage-1 signals:

- stars;
- repository visits and traffic;
- wiki and README navigation use;
- issues opened by outside readers;
- discussions or critiques from external contributors;
- early downloads or trial usage of the engine;
- forks or example adaptations.

These are not vanity metrics. They are signals that the ecosystem is becoming legible.

## Stage-1 public offering

At this stage, GitHub mainly offers:

- a clear multi-repository structure;
- a public protocol entry;
- a runnable local-first engine preview;
- enterprise-facing example cases;
- shared diagrams and navigation assets.

## What we are not asking from the community yet

We are not yet asking for:

- full network adoption;
- legal reliance on protocol outputs;
- production trust in every repository;
- complete alignment with all long-term theory layers.

## Practical community path

The easiest way for an outside reader to engage is:

1. enter through `full-spectrum-commons`;
2. read `full-spectrum-protocol` if they care about schemas and governance language;
3. try `full-spectrum-engine` if they want runnable artifacts;
4. review `full-spectrum-enterprise-governance` if they care about business application.

## Why GitHub first

GitHub is the right Stage-1 carrier because it naturally supports:

- public reading;
- versioned iteration;
- issues and critique;
- pull requests and RFCs;
- lightweight trust building through visible history.

It is a good place to test whether the ecosystem can attract genuine outside interest before building a heavier independent community platform.

## Transition condition to Stage 2

Move beyond Stage 1 only when at least some of the following are true:

- outside users can run the engine with low friction;
- protocol schemas are stable enough to be referenced;
- enterprise examples are understandable to non-authors;
- repeated external questions reveal real demand for stronger coordination.

When that happens, it becomes reasonable to invest in:

- a stronger official community site;
- deeper protocol-network features;
- structured guardian participation;
- contribution and frequency-economy mechanisms.
