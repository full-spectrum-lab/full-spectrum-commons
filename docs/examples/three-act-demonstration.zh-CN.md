# 让全频谱转动一次：先看三处局部机制

[English](./three-act-demonstration.md) · [证据与复跑说明](./evidence/three-act-20261012/README.md)

客户说：“我要退款。”AI客服回答：“可以给您全额退款。”它有权承诺吗？证据不足时该怎么办？

今天从这件事开始，不从大架构图开始。**案例是合成的，程序已经实际运行。** 三个运行相互独立，第三幕没有消费前两幕的产物；不是完整递归、四产品联合运行或真实客户交易。

悲悯协议是最高原则，悲悯宪章是约束；工程是承接，不是体系的全部定义。本次也没有完整验收原则或宪章条款。

## 第一幕：说得出口，不等于有权承诺

固定输入中的客服承诺全额退款，但没有退款权限，人工审核未完成。程序生成事件、上下文、主体边界清单、输出封套、企业回写对象和阅读报告。

实际输出标记高风险，要求人工审核；`allow_auto_reply`、`allow_commitment`、`allow_auto_execution`均为`false`。样例指定客服主管和售后审核队列。

[亲自看结果](./evidence/three-act-20261012/ecommerce/enterprise-writeback.json)：这是明确的限制字段与交接建议，不是现实退款按钮已锁住，也不是工单已送达。样例角色不是对真实企业授权的认定。输入按固定规则求值，不证明系统自行读懂了全部平台与商家规则。

这一幕看见的是：把“说了什么”和“有没有权”分开，并留下可检查对象。它没有裁定客户是否最终应该获得退款。

## 第二幕：换成物流，共同结构不等于相同规则

冷链样例的问题是温度证据不完整、人工审核未完成。程序仍生成同类治理对象，但输出理由、建议与复核安排改变。

| 观察点 | 电商退款 | 冷链物流 |
|---|---|---|
| 原因 | 未经授权的退款承诺 | 物流证据不完整 |
| 样例复核角色 | 客服主管 | 物流质量主管 |
| 样例队列 | 售后审核 | 冷链审核 |
| 共同限制 | 禁止自动承诺、执行，要求人工审核 | 禁止自动承诺、执行，要求人工审核 |

[查看物流结果](./evidence/three-act-20261012/logistics/enterprise-writeback.json)，与第一幕并排比较。两个样例各6份实际产物与各自固定Golden字节一致，各5份JSON通过固定源码内的Schema检查；8项回归测试通过。

这支持两个固定领域中的结构复用，不支持任意行业直接接入，不是数学同构证明，也不是系统已读取真实温控设备。
